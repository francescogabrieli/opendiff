# Support

## Usage questions

Before opening an issue:

1. confirm Node.js satisfies the version in `package.json`;
2. run `opendiffs --help`;
3. run `opendiffs validate` from the target Git repository root;
4. search existing issues;
5. retry with the latest OpenDiffs release or `main`.

Open a GitHub issue for reproducible bugs or documentation gaps. Include the OpenDiffs version, operating system, Node.js version, exact command, sanitized output, and a minimal reproduction when possible. Never attach proprietary source code or a sensitive `.opendiffs/review.json` unless you have permission to share it.

Feature ideas should describe the review problem and desired behavior rather than only a proposed implementation.

## Security reports

Use the private process in [SECURITY.md](SECURITY.md), not a public support issue.

## Service level

OpenDiffs is maintained as an open-source project. Response times are best effort, and opening an issue does not guarantee implementation or a release date.

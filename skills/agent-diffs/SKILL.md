# OpenDiff

Use this skill when the user asks you to present or review the changes you have just implemented. OpenDiff is a local renderer, not a second reviewer.

The renderer is local-first: it reads `.agent-diffs/review.json` for the narrative and calculates the unified diff from the repository working tree. Never paste the full diff into the JSON and never ask another model or agent to reinterpret the change.

## Non-negotiable rules

1. The review must be generated by the same agent that implemented the changes. Do not delegate the explanation to a second model or another agent.
2. Describe only behavior supported by the diff, the code you read, and the tests you ran. If a decision is uncertain, label it as an assumption.
3. Order sections by the most useful path to understand the change, not by file path or alphabetical order.
4. Do not put the full diff in `review.json`. The renderer reads the real Git diff from the working tree.

## Workflow

### 1. Capture context before editing

From the repository root:

```bash
git rev-parse --show-toplevel
git rev-parse HEAD
git status --short
git diff --name-only
```

Record the commit as `baseCommit` and note files that were already modified. Do not silently attribute pre-existing changes to yourself.

### 2. Implement and verify the task

Implement the user’s request using the repository’s conventions. Run the narrowest relevant tests first, then typecheck or build when appropriate. Record every command and whether it passed. Explicitly list checks that could not be run.

### 3. Analyze the final diff

Read the complete diff, including new untracked files. Identify the primary mechanism, dependent integration changes, persistence or error handling, and tests. Group files and hunks by meaning; one file may appear in multiple sections.

### 4. Write `.agent-diffs/review.json`

Use schema version `1.0` and include:

- `project`, `review`, `git`, and `stats` metadata;
- an ordered `sections` array;
- concrete explanations, impact, and precise file/line/symbol references;
- executed and skipped tests;
- concrete risks and assumptions;
- an honest `completion` status (`complete`, `partial`, or `blocked`).

Every section needs at least one reference. A reference must contain `file`, `newLines`, `oldLines`, `kind`, and a stable `id`. Keep line ranges aligned with the final diff.

### 5. Validate and open

If the repository has not been initialized yet, run:

```bash
agent-diffs init
```

This creates `.agent-diffs/config.json`, adds generated artefacts to `.gitignore`, and prints the skill installation command. From the OpenDiff checkout, the Codex skill can be installed with:

```bash
agent-diffs skill install
```

It does not overwrite an existing installed skill unless `--force` is supplied.

Run the renderer from the repository root:

```bash
agent-diffs validate
agent-diffs render
agent-diffs open --no-open
```

Or use `agent-diffs review` for the complete flow. If validation reports an invalid reference, fix the JSON instead of opening an unexplained review. Return the local URL and a short summary of the implementation and test state.

`agent-diffs review --base HEAD --context 6 --no-open` is the equivalent one-shot command. Use `agent-diffs export --output review-export` when a portable static folder is useful. If validation reports an unresolved reference, the renderer can still show it as a warning, but the agent should correct the line range whenever the final diff is known.

## What the renderer handles

The renderer owns layout, syntax highlighting, line numbers, statistics, section-to-line anchors, guided scrolling, file expansion, context controls, local state persistence, stale fingerprint detection, and binary/rename/deleted/lockfile presentation. It does not invent explanations, run an agent, upload repository content, or automatically rewrite stale review data.

## Explanation quality

Explain the problem, the chosen approach, the relationship between touched files, and observable impact. Do not describe every line, restate the programming language, or claim security or correctness properties that the diff cannot prove.

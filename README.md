# OpenDiff

OpenDiff turns code written by coding agents into guided, interactive local reviews. The agent writes the narrative; OpenDiff renders that narrative beside the real Git diff, grouped by intent instead of file order.

The UI is deliberately focused on the reading rhythm of a Linear-style guided review: a linear path on the left, the diff in the centre, and the explanation contextually attached on the right.

![OpenDiff guided review](docs/opendiff-preview.png)

## Try it

OpenDiff does not silently show fixture data when a repository has no review. To explore the UI explicitly:

```bash
npm install
npm run dev
```

Then open `http://localhost:4173/?demo=1`.

For a real repository, initialize the local artefacts and render the review generated by your agent:

```bash
npm run agent-diffs -- init
npm run agent-diffs -- validate
npm run agent-diffs -- review --no-open
```

The generated review is served locally at the URL printed by the CLI. The renderer reads `.agent-diffs/review.json` and calculates the current working-tree diff itself; it never trusts a diff copied into the JSON.

## Install the skill

The supported first-class workflow is Codex:

```bash
npm run agent-diffs -- skill install
```

The command installs `skills/agent-diffs/SKILL.md` into `~/.codex/skills/agent-diffs`. It will not overwrite an existing skill unless `--force` is supplied. Manual installation remains possible:

```bash
cp -R skills/agent-diffs ~/.codex/skills/agent-diffs
```

Ask the agent to use the OpenDiff skill while implementing the task. The same agent must capture the base commit, record the initial working tree, implement and verify the change, read the final diff, group it into a useful reading path, write `review.json`, validate the references, and open the local review. OpenDiff is not a second AI reviewer.

## CLI

```text
agent-diffs init                         create config and .gitignore entry
agent-diffs skill install                install the Codex skill
agent-diffs validate                     validate schema, base, and references
agent-diffs render                       materialize local review data
agent-diffs open --no-open               start the local server without opening a browser
agent-diffs review --base HEAD           validate, render, and open
agent-diffs export --output review-dir   export a portable folder
```

Useful options are `--base REF`, `--context N`, `--port PORT`, `--no-open`, and `--force`. The CLI includes staged, unstaged, and untracked files by default, respects `.agent-diffs/config.json`, detects renamed/deleted/binary files, and reports a changed working tree as stale instead of rewriting the explanation automatically.

## Review data

`.agent-diffs/review.json` contains only the agent-authored interpretation: title, summary, ordered sections, explanations, impacts, references, tests, risks, assumptions, and completion status. A reference points to a file and new/old line range:

```json
{
  "id": "ref-coordinator",
  "file": "src/auth/refreshCoordinator.ts",
  "symbol": "createRefreshCoordinator",
  "kind": "primary",
  "newLines": { "start": 12, "end": 58 },
  "oldLines": null,
  "description": "Owns the shared refresh operation."
}
```

The complete JSON schema is in [`schemas/review.schema.json`](schemas/review.schema.json). Invalid references do not prevent the page from opening: they are marked and shown as warnings so the user can still inspect the rest of the review.

## Fixtures and tests

Deterministic browser fixtures are available through `?fixture=small`, `medium`, `rename`, `deleted`, `lockfile`, `invalid`, and `stale`; see [`examples/fixtures/manifest.json`](examples/fixtures/manifest.json). The portable small pair is in [`examples/small-review/`](examples/small-review/).

```bash
npm test
npm run test:e2e
npm run build
```

The test suite covers the diff parser, Git collection and fingerprinting, schema/render integration, and the guided browser flows.

## Privacy and scope

OpenDiff is local-first. There are no accounts, telemetry, CDN assets, remote code uploads, cloud history, pull-request integrations, comments, approvals, merge actions, or separate reviewer models.

## Roadmap

The next natural additions are watch mode, richer static export, more agent installers, side-by-side diff mode, and optional editor integration. The core promise stays the same: make the work an agent just completed easy to understand.
